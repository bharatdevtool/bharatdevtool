Everything you need to know about UUID generation

A UUID (Universally Unique Identifier) is a 128-bit identifier formatted as 32 hexadecimal digits in the pattern xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx. UUIDs are used to uniquely identify records in databases, distributed systems, APIs, and software applications without requiring a central coordinating authority. There are several UUID versions — v1 (time-based), v4 (random), and v7 (time-ordered random) are the most widely used.

UUID v1 is time-based and encodes the current timestamp plus random node bits. It is monotonically increasing within the same millisecond sequence, making it useful for time-based ordering.

UUID v4 is randomly generated — it has no structure beyond version and variant bits, making it the most widely used UUID for privacy-sensitive use cases. Your browser's crypto.randomUUID() generates v4 UUIDs.

UUID v7 is a newer standard (RFC 9562) that encodes a millisecond-precision Unix timestamp in the most significant bits, making UUIDs naturally sortable by creation time while still being random enough to avoid collisions. It is ideal for database primary keys where you want time-ordering.

UUIDs are used as:

  • Primary keys in databases (PostgreSQL, MySQL, MongoDB)
  • Unique identifiers for REST API resources
  • Session tokens and request correlation IDs
  • Idempotency keys for payment and order APIs
  • Unique file names to avoid collisions
  • Distributed tracing and logging identifiers

UUID v4 is ideal for most cases; UUID v7 is preferred when sortability by creation time is important (e.g. database primary keys).
