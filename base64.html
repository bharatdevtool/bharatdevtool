Everything you need to know about Base64 Encoder/Decoder

Base64 encoding converts binary data or text into a string of ASCII characters using 64 characters (A-Z, a-z, 0-9, +, /). It's commonly used to encode data for transmission over protocols that only support text, such as email attachments, data URLs, and API responses. Base64 encoding ensures data integrity and compatibility across different systems.

Simply paste or type your text into the input field and click the "Encode" button. The tool will automatically convert your text to Base64 format. You can encode any text, including special characters, Unicode characters, and even binary data represented as text.

Paste your Base64-encoded string into the input field and click the "Decode" button. The tool will convert the Base64 string back to its original text format. If the Base64 string is invalid, the tool will display an error message.

Base64 uses 64 characters: uppercase letters (A-Z), lowercase letters (a-z), digits (0-9), plus sign (+), and forward slash (/). The equals sign (=) is used as padding at the end of Base64 strings when needed.

This tool focuses on text-to-Base64 and Base64-to-text conversion, which is the most common use case for developers.

When enabled, this option treats hexadecimal strings (like "FB EF FF FF" or "00 01 02 03") as binary data instead of text. The tool will automatically remove spaces and convert each pair of hex digits into actual bytes before encoding to Base64.

Example: Input "FB EF FF FF" with this option enabled will be converted to the bytes [251, 239, 255, 255] and encoded as ++///w==. Without this option, it treats "FB EF FF FF" as text and encodes it as RkIgRUYgRkYgRkY=.

This is useful when working with binary data represented in hexadecimal format, such as cryptographic keys, hash values, or raw binary data.

When enabled, this option processes escape sequences in the format \xNN (where NN is a two-digit hexadecimal number) and converts them to their corresponding byte values before encoding.

Example: Input \x48\x65\x6C\x6C\x6F with this option enabled will be converted to "Hello" and then encoded as SGVsbG8=. Without this option, it treats the backslashes and 'x' as literal characters.

This is useful when working with escape sequences commonly used in programming languages like C, JavaScript, or Python, where \x48 represents the byte value 0x48 (which is the ASCII character 'H').

URL-safe Base64 (also called Base64URL) is a variant of Base64 encoding designed for use in URLs and filenames. It replaces characters that have special meaning in URLs:

  • + (plus sign) is replaced with - (minus sign)
  • / (forward slash) is replaced with _ (underscore)
  • Padding characters = can optionally be removed

Example: Standard Base64 ++///w== becomes --___w== in URL-safe format.

This format is commonly used in:

  • JWT (JSON Web Tokens) tokens
  • OAuth 2.0 authorization codes
  • URL parameters and query strings
  • Web Crypto API
  • Any scenario where Base64 data needs to be safely included in URLs

When decoding, the tool automatically detects URL-safe Base64 and converts it back to standard Base64 before decoding.

When enabled, this option removes the padding characters (=) from the end of the Base64-encoded output. Base64 encoding uses padding to ensure the output length is a multiple of 4 characters.

Example: Input "Hello" normally encodes to SGVsbG8= (with one padding character). With "Strip padding" enabled, it becomes SGVsbG8 (without the =).

Padding is optional in many contexts and can be automatically added back when decoding. Some systems prefer Base64 without padding for cleaner URLs or more compact storage. The tool can decode Base64 strings with or without padding automatically.

Note: When using URL-safe Base64, padding is often removed by default, as it's not needed for URL compatibility.
